# AUFGABE: Platzierung an die GEMESSENEN Volumen anpassen (Fächer wirklich einrechnen) + Prüfer dafür

## Warum (Befund vom 14.09.2026, live gemessen)

Der Neuaufbau des Blatts ist **elektrisch korrekt** (80 Bauteile, 50 Netze, 233 Verbindungen,
pin-für-pin 0 Abweichungen, bridge-check 0, NC-Marker gesetzt), aber `sch clusters` meldet
weiter **2 ERROR**: ein Überlappungspaar mit ~10 Einheiten und ein Bauteil, dessen rechte Kante
die Blattfläche verlässt. Ursache: `plan_layout.py` rechnet den Platz der Marker-Fächer nur
**geschätzt** ein. Die Schätzung ist zu klein — gemessen brauchen Bauteile mit langen Netznamen
(`SPARE_IO15_RAW`, `SPARE_AIN_RAW`, `LIGHT_AOUT`) **bis 384 Einheiten Breite und 223 Höhe**
(Bauteil **plus** eigene Marker/Stichdrähte).

**Die echten Volumen liegen vor** (vom Koordinator live gemessen, `sch clusters --json`):

```
hardware/easyeda/raw/measured_volumes_2026-09-14.json
  parts.<REF> = { module, vol_w, vol_h,      # Volumen inkl. eigener Marker/Stiche
                  body_w, body_h, markers, wires }
  nutzbar = { minX: 12, minY: 12, maxX: 2326, maxY: 1640 }   # A2
```

## Aufgabe

1. **`plan_layout.py` packt mit den gemessenen Volumen** statt mit Schätzungen:
   - Je Bauteil die gemessenen `vol_w`/`vol_h` aus der JSON als Platzbedarf verwenden
     (Fallback-Schätzung nur für Bauteile, die dort nicht stehen — im Bericht nennen).
   - Ein Part-Volumen darf **nicht** aus dem Block herausragen und **kein** anderes Volumen
     (gleicher oder fremder Block) berühren: zwischen zwei Volumen **≥ 20 Einheiten** Abstand.
   - Block-Rechtecke (und damit `frames.json`) so bemessen, dass sie ihren Inhalt mit
     **≥ 20 Einheiten Rand** umschließen; Blatt bleibt **A2**, alle Volumen bleiben in
     `nutzbar` (x 12…2326, y 12…1640). Blöcke dürfen sich nicht überlappen.
   - Wenn es mit 12 Blöcken auf A2 zu eng wird: **Blöcke dürfen umverteilt/vergrößert** werden
     (z. B. ein Modul in zwei Reihen), aber **kein Modul darf auf eine zweite Seite wandern**
     (eine Seite, ein Bild). Im Bericht sagen, wie voll das Blatt danach ist (belegte Fläche
     in %).
2. **Prüfer ergänzen:** `hardware/easyeda/scripts/check_plan_fit.py` — liest
   `raw/placement.json` + `raw/measured_volumes_2026-09-14.json` (+ `raw/frames.json`) und prüft
   offline: (a) jedes Volumen vollständig im nutzbaren Bereich, (b) keine zwei Volumen näher als
   20, (c) jeder Rahmen umschließt seinen Inhalt mit ≥ 20, (d) Blöcke überlappen nicht.
   Exit 1 bei Verstoß, Rohzahlen auf stdout. In `hardware/easyeda/README.md` als Schritt der
   Nachbau-Reihenfolge aufnehmen.
3. **`raw/` neu erzeugen** (nur Dateien, **keine Live-Aufrufe**):
   ```
   cd hardware/easyeda
   python3 scripts/build_ir.py && python3 scripts/plan_layout.py && python3 scripts/build_autoconnect.py && python3 scripts/netclass_spec.py
   python3 scripts/check_plan_fit.py        # muss Exit 0 liefern
   ```
   Netzliste/BOM bleiben unverändert: `raw/ir_report.txt` → **80 Bauteile, 50 Netze**,
   `check_ir_netlist.py` → **0 Abweichungen**, `hardware/design/report.py` → **29/29**.
4. **Bericht:** neue Block-Rechtecke (alle 12), die je Modul belegte Fläche, Blattauslastung in %,
   Ergebnis von `check_plan_fit.py` als Rohzahlen, plus ehrlich die Restpunkte
   (was offline weiterhin nicht sicher vorhersagbar ist: die Fächerrichtung wählt erst der
   Autoconnect-Solver live).
